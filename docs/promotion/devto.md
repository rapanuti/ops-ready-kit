# Generating Operational Docs From Repository Signals

I am building `ops-ready-kit`, an open source CLI that analyzes a repository and generates operational documentation:

- Runbooks
- N1 and N2 operations guides
- Architecture summaries
- Deployment notes
- Security checklists
- Production readiness checklists
- Optional Docker, Compose, Kubernetes, GitHub Actions, and health check templates

The project is early, but the motivation is simple: many teams know they need operational docs, but starting from a blank page is slow. Repository signals can provide a useful first draft that humans review and improve.

Repo: https://github.com/rapanuti/ops-ready-kit
